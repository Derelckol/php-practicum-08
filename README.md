# Практична робота №8 — Безпека PHP-застосунків

**Варіант 15 — Система бронювання квитків (кіно/події).**

Навчальний PHP/MySQL-застосунок із захистом від SQL Injection, XSS та CSRF. Детальний аудит, виправлення й фактичні результати перевірок наведено у [звіті](REPORT.md).

## Функціональність

- Список подій, фільтрація за місцем проведення, додавання, редагування та видалення.
- Купівля квитка з атомарним зменшенням залишку місць і захистом повторного надсилання форми.
- JSON API та кешування списку подій без вільних місць.
- Підготовлені PDO-запити, екранування HTML, CSRF-токени, серверна валідація й обробка помилок.

Основа — API практичної №7 та CRUD-форми №4. Попередні роботи залишено без змін. Автентифікація та ролі користувачів у навчальній моделі відсутні; CSRF-захист не замінює авторизацію.

## Запуск на macOS

Потрібні PHP 8.1+ з pdo_mysql, mbstring; MySQL; для тестів Python 3 і pcntl.

```bash
brew install php mysql
brew services start mysql
cd php-practicum-08
mysql -h 127.0.0.1 -u root -p < schema.sql
export DB_HOST=127.0.0.1 DB_PORT=3306 DB_NAME=php_practicum_08 DB_USER=root
# Якщо пароль потрібен (zsh), введіть його без збереження в історії:
read -s 'DB_PASSWORD?Пароль MySQL: '; export DB_PASSWORD
php -S 127.0.0.1:8000
```

Відкрити [застосунок](http://127.0.0.1:8000/index.php). Для локального root без пароля можна пропустити read і використовувати `mysql ...` без `-p`. Не імпортуйте schema.sql повторно в заповнену базу: скрипт розрахований на нову таблицю і навмисно не містить DROP. `.env` автоматично не завантажується — конфігурація через середовище. Для спільного сервера використовуйте окремого MySQL-користувача з правами лише на цю базу.

API: GET `api.php?resource=events`, `&venue=...`, `&id=1`, `&action=soldout`; POST `api.php?resource=events` для створення та `api.php?resource=events&action=buy&id=1` для купівлі. Створення приймає title, event_date (`YYYY-MM-DD HH:MM:SS`), venue, seats_left. Обов'язкові session cookie і CSRF-токен для POST.

## Тестування

Створіть окрему тестову базу, не використовуйте робочу:

```bash
sed 's/php_practicum_08/php08_test_local/g' schema.sql | mysql -h 127.0.0.1 -u root -p
DB_NAME=php08_test_local php -S 127.0.0.1:8001
# В іншому терміналі:
python3 tests/security.py http://127.0.0.1:8001
DB_NAME=php08_test_local php tests/concurrency.php
find . -name '*.php' -exec php -l {} \;
```

Тести видаляють тільки власні створені записи; у разі переривання вони можуть залишитися в тестовій базі. Параметри DB_USER/DB_PASSWORD мають бути встановлені також для concurrency.php.


Очікуваний результат: `ALL CHECKS PASSED` для HTTP-тестів, одна успішна купівля останнього місця для конкурентного тесту та відсутність синтаксичних помилок. Зафіксовані результати й межі перевірок наведено у [REPORT.md](REPORT.md).
